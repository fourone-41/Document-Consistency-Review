关系抽取技术核心：把零散节点连成证据链

节点抽取只回答"文档里有什么"，关系抽取要回答"这些内容之间如何互相证明、约束、覆盖"。系统先在单份文档内建立局部关系，再跨文件发现需求、设计输入、风险、控制措施、测试、法规之间的追溯链；三层发现架构从精确匹配逐步扩展至开放式语义探索，覆盖预定义和未知关系类型。

设计原则
输入不是全文，而是节点 LLM 已把文档变成结构化节点，关系抽取只在节点之间判断连接，大幅减少噪声和 token 消耗。
规则先行，LLM 补充 字段里已明示的关系（负责人、清单条目、编号前缀）由规则直接生成，零 LLM 调用；规则覆盖不到的语义关系才送模型判断。
先召回，再判定 不让模型两两穷举所有节点。规则、ID、法规知识生成候选对，LLM 只对候选对做判断，保证精度与速度。
置信度分层输出 规则生成 → high，LLM 批量配对 → medium，开放候选经二次验证 → medium，供后续报告和 Neo4j 导入分级使用。
三层发现架构
①
精确规则层 通过 ID 字段、文件名、人名、编号前缀直接匹配，无 LLM 调用，结果稳定可复现。适用于风险-控制措施（编号关联）、DHF 清单-文档（文件名）、人员去重（姓名）。 置信度 high
②
LLM 批量语义层 对规则未覆盖的节点，按 12 种法规引导关系批量配对：源列表 S1…Sn 与目标列表 T1…Tm 同批输入，模型只输出明确匹配的 S编号-T编号，便于解析。每侧批次最多 40 项，法规条款要点随 Prompt 注入。 置信度 medium
③
开放候选发现层 三个子模块（桥接实体、语义嵌入、图模式传播）并行产生候选，去重后送开放式 LLM 验证。不限定关系类型，允许模型命名"新关系：XXX"，捕捉法规引导未预设的隐性联系。 置信度 medium（验证后）

抽取执行管线
1. 节点准备按类型整理节点列表，保留 id、名称、描述、数值、单位、来源文件等摘要字段。
2. 文档内规则边从明确字段直接生成 SIGNED、LISTS_FILE、HAS_REVIEW_ITEM 等确定关系。
3. 文档内 LLM 边让模型补充 DERIVES_FROM、MITIGATED_BY、VERIFIED_BY 等隐式关系。
4. 法规引导召回按 12 种 REGULATORY_GUIDES 配对源/目标类型，规则层先行，剩余送 LLM。
5. LLM 批量配对源列表 S1…Sn 与目标列表 T1…Tm 成批输入，模型输出 Sx-Ty 格式。
6. 关系入库每条关系带类型、来源、目标、标准依据、置信度，进入 JSON、Neo4j 和报告。
双轨抽取详解

A. 文档内关系抽取

目标：在单份文档内部先形成小图谱，解决"这个文件内部谁和谁有关"。

规则推导先行 从明确字段直接生成关系，稳定、廉价、可解释。例如 PlanTask.owner 生成 RESPONSIBLE_FOR，文档清单生成 LISTS_FILE，评审表行生成 HAS_REVIEW_ITEM。
SCHEDULESLISTS_FILESIGNEDHAS_DETAILREPORTED_IN
LLM 补充隐式关系 把同一份文件里的节点摘要发给模型，让它判断哪些节点存在语义关系。例如某条风险是否被某控制措施缓解，某个测试是否验证了某项设计输入。
DERIVES_FROMMITIGATED_BYVERIFIED_BYREVIEWS
为什么不能只用 LLM 一次性让 LLM 找所有关系召回率低，且容易漏掉结构性关系；规则先托底、LLM 再补语义，是更稳定的双轨方案。
合并去重写回 JSON 规则边和 LLM 边按 type/from/to 去重，写入每份文件的 _edges 字段，作为合并图谱的一部分。

B. 跨文档关系抽取

目标：跨文件发现"应当存在"的追溯、验证、覆盖和实现关系。

法规知识引导候选范围 REGULATORY_GUIDES 定义 12 种应搜索的关系方向，并注入对应标准的条款要点（regulatory_clauses.yaml），告诉系统"应在哪些节点类型之间找证据链"。
Requirement→DesignInputDesignInput→TestRisk→RiskControlRegulation→Requirement
多策略分级召回 不同关系用不同方式召回：风险与措施看编号前缀，清单与文档看文件名，需求与测试看描述和数值，人员一致性看姓名。
精确类（high）ID 前缀、文件名、人名
语义类（medium）关键词重叠、描述相似、数值一致
LLM 批量语义配对 源列表和目标列表分批（≤40 项/侧）交给 LLM，格式为 S1-T3。法规条款要点随 Prompt 注入，提升专业语境下的匹配精度。
置信度与审查依据 每条边记录 confidence、依据标准（如 ISO 13485 7.3.3）、源文件和目标文件。高/中置信度关系进入 Neo4j，低置信度保留给报告和人工复核。
开放候选发现（层③详解）

层①②均基于预设的 12 种法规引导关系。层③不设类型约束——三个子模块并行产生候选对，再由开放式 LLM 自由判断关系类型（含"新关系：XXX"），捕捉法规引导未预设的隐性联系。

🌉
桥接实体发现
识别跨文档类型共享的"桥接节点"：例如同一组件编号既出现在 BOM 文档也出现在设计输入表，或同一测试条件被多份验证报告引用。桥接实体往往是隐性跨文档关系的入口。
🔍
语义嵌入检索
对节点描述做向量嵌入，在高维语义空间计算相似度，找出描述内容接近但来自不同文档的节点对。尤其适合处理"中文需求 ↔ 英文测试描述"等跨语言场景。
📊
图模式传播
统计层①②已建立的边中出现频率 ≥ 3 的路径模式（A→B→C），当某条 A→B 存在但 B→C 缺失时，将 C 候选项推送给开放式 LLM 验证，自动补全断链。
三路候选合并 · 对象去重 三个子模块并行产出后，按节点对象 ID 去重，避免重复发送相同候选对给 LLM。
→
开放式 LLM 验证（批次 20 对） 不限定关系类型，允许 LLM 自由判断并命名关系（包括"新关系：协同测试"等），"无关系"则过滤，结果以 medium 置信度写入图谱。
