Context Recovery

Report

从 agent_runs[]、证据核验和裁决结果生成最终报告。

当 Challenge 输出 needs_more_context 时，Context Recovery 补证后回到 Orchestrator；Orchestrator 再根据新的上下文重新决定下一轮派发。

Orchestrator 动态调度闭环

每一轮都由 Orchestrator LLM 判断是否继续，而不是由固定代码路线决定。

1

读取黑板

读取 project_profile、routing policy、候选结果和已有 agent_runs。

blackboard state
2

生成 route_plan

输出 decision、reason 和 assignments。

continue / stop / human_review
3

执行派发

Python 校验 Agent 名称和 task_type，然后真实调用被派到的 LLM Agent。

no cache read
4

记录运行

每次 Agent 调用追加到 agent_runs[]，供下一轮 Orchestrator 读取。

RUN-0001RUN-0002
5

进入闭环

当 Orchestrator 输出 stop 或 human_review，进入 Evidence Gate 与后续报告链路。

review closure
