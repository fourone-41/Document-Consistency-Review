# Dimension Axis Skill（维度轴 · 7 维横扫）

## Purpose

这是 DHF/DMR 审核**双轴**里的第二根主轴。阶段轴（`stage-01..stage-11` + `dmr-mfg-sop` 各 skill）顺着设计控制的结构（阶段→阶段、工种→工种）查"**每个人的活干完没有**"=完备性；维度轴**横切结构**，按"问题类型"捞"**大家的活对不对得上**"=一致性。

它解决的是阶段轴的**结构性盲区**：错误最爱藏在工种与工种、阶段与阶段的**接缝**里，而按阶段切正好把接缝劈成两半，谁都不完整看一遍。具体地，下面这几类错误，顺着结构（顺阶段、顺参数、顺角色、顺清单）查一定会漏：

- 全库**所有文件**的版本号在缓慢漂移——每份单看都有版本号，合在一起才看出方向倒置/多版并存。
- 全库**所有 BOM** 的跨表对账（EBOM↔ABOM↔包装 BOM↔WI 物料↔工序大纲）——任何两张单看都自洽，配平起来才发现螺钉对不上。
- 非相邻阶段之间、同一文件内部两处口径打架——这根本不在"流程链"上。

**朴素做法为什么不行**：一份一份顺着读，会系统性漏掉"单看任何一份文件都正常、只有跨文件比对才暴露"的一整类错误。让一个大 agent 一口气读完所有文件找矛盾，上下文窗口装不下整个 DHF，"大海捞针"式比对召回率极低且不可复现。所以维度轴的解法是：**按 7 种问题类型各派一个 agent 横扫全库，能确定性判的先用脚本（近零误报），其余用 LLM 横扫求召回，再经去重 + 对抗证伪压误报。** 实证上，维度轴在阶段轴跑完之后，PT9L 净增 +31（73→104）、PT9S 净增 +23（146→169），合计 +54 条经去重 + 证伪确认的真问题——**最大增量恰好落在阶段轴最薄弱的维度**（断链/BOM/角色/矛盾），这从数据上证明两轴扫的是不同的错误集合，不是冗余。

## 何时用

- **前置条件**：阶段轴（`stage-01..stage-11` 各阶段 + `dmr-mfg-sop`）已全部跑完，已产出该阶段轴的错误候选（用于后续去重）。维度轴是"再扫一遍横切"，不是替代阶段轴。
- 已完成提取层：`运行参数长表.csv`（SSOT 参数实例长表）已沉淀，因为**维度轴的数值/不收窄/BOM 三维全站在这张表上**。
- 已完成转换层：全库 `*_MD/` 已就绪（反向完备性、版本漂移、矛盾措辞、模板残留都要 grep 整个转换语料）。
- 当你需要回答"这一堆文档互相对不对得上"，而不只是"每个阶段自己全不全"。

## 七个检查维度（维度轴的全部内容）

每个维度 = 一类可判定的子问题 + 一条算法思路 + 是否有确定性脚本。

| 维度 | 查什么 | 算法思路 | 确定性脚本 | 实证净新增(PT9S/PT9L) |
|---|---|---|---|---|
| **数值一致** | 同一参数多处取值，区间+单位归一比对 | 区间算术 + 单位归一 + 精确判定（剔写法误报） | `check_params_numeric.py` | 0 / 3 = **3** |
| **可追溯断链** | 需求→输入→输出→验证→确认 逐参数查断链；每个风险控制有无验证；DHF清单每项是否落地 | 属性图多跳；闭世界完备性约束（LLM 横扫） | —（LLM） | 6 / 7 = **13** |
| **不收窄** | 下游区间 ⊆ 上游（量程/人群/环境/精度） | 区间包含双向判定 | `check_params_numeric.py`（同表，判方向） | 3 / 2 = **5** |
| **矛盾措辞** | 对立陈述：需临床 vs 免临床/版本日期打架/同参数互斥值/单文件内部判据矛盾 | 对立子断言对撞 + 簇级长上下文整读（LLM） | —（LLM） | 3 / 5 = **8** |
| **BOM对账** | EBOM/ABOM/包装BOM/组件清单/WI物料/工序大纲/PFMEA 跨表配平 | 列级 schema 匹配 + 单元格 key-join diff + 公差 | `check_table_diff.py`（同构）/ `check_bom_crosswalk.py`（异构） | 3 / 6 = **9** |
| **版本漂移** | 同号多版本/整树副本/多版并存未作废/方向倒置 | MinHash + containment 归族定方向（LLM/脚本） | —（LLM；可上 Tier2） | 4 / 3 = **7** |
| **角色串联** | 同一工程师名下文件参数自洽；评审独立性（一人多职） | 按 7 角色归桶 + 跨型号锚点对照 | `check_residue.py`（残留/串号机械层） | 4 / 5 = **9** |

> 观察：**越成熟的 DHF，数值/BOM/版本类跨文档冲突越多**（PT9L 有完整 DMR/工序，数值3+BOM6；PT9S DMR 未产出，断链/版本/不收窄为主）。维度的"战果分布"本身就是 DHF 成熟度的一个指标。

横向参数槽位、7 角色串联、反向完备性，分别是上表"数值一致/不收窄""角色串联""可追溯断链"维的具体机制，下面强制工作流逐一落到命令。

1. **先加载通用方法 skill**：`D:\AI_0415\03DHF\skill\SKILL.md`（working-method）。沿用它的实际看到/一步一验/诚实标 UNKNOWN/末尾回🐱纪律。

2. **确认前置产物齐了**（齐了才有横扫的地基）：

   - 不要信终端乱码；用 `Path.exists()` 判存在，不要把终端显示的问号当真文件名。

3. **维度①+③（数值一致 / 不收窄）· 横向参数槽位 · 确定性脚本**。把一个参数横着拉成一行（"槽位"），同槽出现 ≥2 个归一后仍不同的值即冲突；不收窄是同一张表上判"下游区间是否 ⊆ 上游"。
   ```bash
   python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_params_numeric.py" \
     "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-运行参数长表.csv" \
     --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-数值冲突-维度轴.csv"
   ```
   它做：`canon()` 同义词归一（`动态电流/运行电流/工作功耗→工作电流`，带负向护栏 `整机重量` 不吃 `整箱/外箱/包装/托盘重量`）→ 单位归一（℃/℉、A/mA/µA、mm/cm/in、s/分/时、g/kg）→ 五种形态解析（区间/容差/边界/单点/特殊：IP等级、尺寸排序三元组、"最大42.9最小32"归一成区间）→ 按 (canon, qualifier) 分组（限定词"静态/动态/物温/体温"防结构性误报）→ 区间求交（点落区间判一致**不报**，≥2 个不同区间才报）。**写法噪声不报**：`34-43` vs `34~43` 归一后同签名。降噪：精度/分辨率（带温度段+重复性歧义）移交 LLM；过滤"实测/水槽/号机/逐次"原始测量数据。

4. **维度⑤（BOM 对账）· 确定性脚本**。同构两表（结构一致）用 diff；跨异构多源（BOM/清单/WI 抽到统一 schema）用 crosswalk。
   ```bash
   # 同构表逐格 diff（含公差）
   python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_table_diff.py" \
     表A.csv 表B.csv --out "PT9L-BOM同构diff-维度轴.csv"

   # 跨异构表对账：输入一张统一"零件记录表"(列=来源,品名,用量,规格,图号,物料编码)
   python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_bom_crosswalk.py" \
     "PT9L-零件记录表.csv" --out "PT9L-BOM对账-维度轴.csv"
   ```
   `check_bom_crosswalk.py`：品名同义词归并（`螺钉/螺丝/screw/自攻`、`传感器/探头/热电堆`，弹簧按正极/负极/双联**不合并**）→ 按零件聚合每来源 用量/规格/图号（WI 多工步求和）→ 跨来源核对：①用量冲突（螺钉 WI 9 颗 vs BOM 10 颗）②规格/图号冲突（EEPROM 三处不一致）③仅部分来源出现（缓冲垫/快速指南在 BOM 缺录、装箱数三方不闭环）。

5. **维度⑦（角色串联）· 模板残留机械层 · 确定性脚本**。按 7 工程师角色（硬件/结构/软件/法规认证/包装/品质/工艺）归桶，查角色内人名/职责自洽 + 评审独立性（一人多职、审核=批准塌缩）+ 跨型号串号。
   ```bash
   python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_residue.py" \
     "D:/AI_0415/03DHF/PT9L_MD" --product PT9L \
     --foreign 血压计,耳机,雾化器,冲牙器 \
     --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-模板残留-维度轴.csv"
   ```
   它机械层查三件：①模板残留（别的型号/品类名混进本项目，靠 `--foreign` + 异类型号前缀）②文件页脚编号/版本 vs DHF 清单一致性 ③占位符未改（`XXXX/待填/TODO/○○`）。**串号的语义判定靠跨型号锚点先验**：`Ma JunWang Di`（PT7 马骏 + PT9L 王迪被复制粘连）、PT7 全链负责人误写成 PT9L 的"王迪龙"——脚本给弱信号"同角色名下两个人名"，定到"它是某型号残留"要拿跨型号锚点对照（LLM/人）。

6. **可选：四件套一键串跑**。
   ```bash

   ```

7. **维度②④⑥（可追溯断链 / 矛盾措辞 / 版本漂移）· LLM 横扫（无确定性脚本，按算法思路做）**。这三维确定性不可靠，**不分阶段、各派一个 agent 横扫全库求召回**：
   - **可追溯断链**：需求→输入→输出→验证→确认 逐参数查断链；每个风险控制有无验证证据；DHF 清单每项是否落地。真例：电流参数下游有验证、**上游设计输入整条没有**（反向断链）；4 份型式试验/EMC 报告**占位"报告编码"无实体却判合格**。

   每条候选必须给 **双向原文引用**（A 文件值 vs B 文件值 + 出处 + 逐字原文 + 节号/页号），拿不到逐字证据判 **NEI**，绝不默认通过、绝不编。

8. **反向完备性（"该有却没有"）· 拿外部强制清单逐条 grep 反查**。方向和①②③相反——不是读文件找错，是拿清单逐条点名查缺。
   ```bash
   # 对清单每一项在全库 MD 做精确子串反查（示例：880.2910 / UDI / 510k）
   # 用 Grep 工具或:
   grep -rn "880.2910\|UDI\|510k" "D:/AI_0415/03DHF/PT9L_MD" || echo "ALL-MISS=反向断链候选"
   ```
   全库**零命中**且市场勾了美国（强制走 FDA）→ 报 **critical 缺失**（法规根没扎）。证据是"全文无 X"的**缺失断言**。**市场护栏**：仅美国市场下，EU 的 EN、中国的 GB 非强制，**正确裁剪它们不算错**，只有反向引用 EN/GB 当美国判定基准才是真错。

9. **去重（vs 阶段轴已有）**。把本轮候选与阶段轴错误总表比对，剔掉阶段轴已抓到的，只留净新增。否则会把同一条重复计两次。

10. **逐条对抗证伪 + 缺失断言特判**。每条候选派一个"挑刺"agent 回正文试图反驳，证据不实/其实一致/写法误报就毙掉（实证毙掉约 1/4：PT9S 33→23、PT9L 37→31）。
    ```bash
    python "D:/AI_0415/03DHF/verify_findings.py" \
      --findings "PT9L-维度轴候选.csv" --corpus "D:/AI_0415/03DHF/PT9L_MD"
    ```
    **关键接缝**：反向完备性的"全文无 880.2910"是缺失断言，证据本就搜不到（它说的就是"没有"）。`verify_findings.py` 必须按 NEG 关键词（`无/未/缺/NEI`）特判，否则会把真缺失误杀成"可疑/幻觉"（初版 41 条真缺失被误判，加 NEG 识别后降到 5 条真可疑）。

11. **汇总净新增**。落到 `<型号>_CHECK\<型号>-新增问题-维度轴.csv`（PT9L/PT9S 实证文件即此名），并入 `<型号>-全链审核-错误总表-含维度轴.csv`。每条带 维度/严重度/双向证据/出处文件/改法/责任角色（`role` 字段直接派工）。

## 与其它层的衔接

- **上游（阶段轴 skill）**：维度轴**必须在** `stage-01..stage-11` + `dmr-mfg-sop` 全部跑完后再跑，它读阶段轴产出的 SSOT 长表与错误总表。两轴正交：阶段轴管完备性（活干完没），维度轴管一致性（对不对得上），盲区互补不重叠。
  - 阶段轴盲区（跨文件同类毛病：全库版本漂移、所有 BOM 配平）→ 维度轴横扫覆盖。
  - 维度轴盲区（有向承接走样：09 设计输出有没有比 06 设计输入写松）→ 阶段轴子轴①（下游≥上游）覆盖。
  - 两轴共漏（"该有却没有"）→ 反向完备性用外部清单点名覆盖。
- **提取层（conversion-toolkit-skill / 转换 + 覆盖台账）**：维度轴的召回上限 = SSOT 长表收录的参数实例数。参数没被抽进表（藏在 OLE/勾选框里），它的漂移永远抓不到——**抽取是天花板**。
- **自验证层（`verify_findings.py`）**：维度轴是高召回低精度的一侧，候选在对抗证伪前不算结论；缺失断言需 NEG 特判。
- **输出层（finalize / gen_report_html）**：净新增并入错误总表，列名与阶段轴一致，下游报告工具复用。

## 边界与踩坑

- **Tier1 确定性脚本是低召回换近零误报**：`check_params_numeric.py` 在 PT9L 数值维只抓 0 组，**不是没冲突，是那批冲突压根不在 408 行长表里**（抽漏了）。低召回的缺口靠 LLM 横扫补，不要因为脚本报 0 就以为"数值都对"。
- **BOM 跨表对账非近零误报**：`check_bom_crosswalk.py` 靠品名模糊归并 + key-join，同义词表/护栏不完备时会误配（把 A 件配给 B 件）。它比纯数值检查更可能误报，结果须人核。同构表 `check_table_diff.py` 更稳，但要求两表 schema 真的一致。
- **维度轴整体高召回低精度**：LLM 横扫的三维（断链/矛盾/版本）必然有误报，**强制走对抗证伪**，证伪前不计入净新增。
- **角色串号靠跨型号先验**：没有"某型号该是谁"的锚点，脚本只能报弱信号"同角色两人名"，定不到"它是 XX 型号残留"。先验来自历史资产，需维护。
- **反向完备性的清单是领域知识、需维护**：清单漏列一条法规，这条缺失就永远查不到；市场护栏方向搞反会把真错放过（裁剪 EN/GB 放过，反引 EN/GB 当美国基准必须报）。
- **一致性≠正确性**：维度轴判"对不对得上、全不全"，**值本身对不对要工程师拍**（传感器几根线、静音是按钮还是开关，由 PM 纠）。可疑值要标出来，但不替工程师做工程决策。
- **NEI 不是失败、缺口也是发现**：抽不到证据如实标 NEI；DMR 文件夹空 = 设计转换未完成，本身是 critical，不是"这个维度没问题"。
- **字段名 ASCII**：机器读的 key（`source_file/canon/qualifier/role/severity/vs_folder`）全英文下划线；值可中文。不要在脚本里硬编码中文路径，从 CSV/manifest/Path 读。
- **平台锁定**：转换依赖 Word COM（仅装 Office 的 Windows）；维度轴脚本本身是纯 Python，但其输入 SSOT 来自该转换链。
