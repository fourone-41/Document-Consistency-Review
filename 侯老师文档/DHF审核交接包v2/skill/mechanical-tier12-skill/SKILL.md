## 目的(解决什么 / 朴素做法为什么不行)

这一层只做**机器能 100% 确证、不需要语义判断**的检查,全部是纯 Python 脚本(标准库即可,个别要 `openpyxl`/`xlrd`),**不调任何大模型**。它的唯一设计目标是一句话:**近零误报(near-zero false positive)**——它说有问题,就一定有问题。

为什么必须有专门的确定性层,而不是把所有检查都交给 LLM:

- **误报的代价远高于漏报。** 机械层每报一条,硬件 PM/工程师都要拿着去翻原文件、找作者核对。10 条里有 6 条是写法差异/单位没归一/实测数据造成的假冲突,复核人就**不再信任整个工具**,真问题也跟着被无视。在跨文件设计审核里,一个会"狼来了"的工具比一个偶尔漏报但报准的工具危险得多。
- **这几类问题本就该确定性做。** "同一参数在两份文件写了两个不同的数""两版 BOM 哪个料号变了哪列""血压计的词混进了体温计 DHF"——这些靠对齐和规则就能定死,上 LLM 既慢、又引入幻觉、还不可复算。
- **朴素做法的具体死法:** 精确字符串比对会把"工作电流"和"动态电流"当两个参数→漏报;按行号对齐两份 BOM,行序一漂移后面全错位→爆几十条假差异;把"34-43"和"34~43"当两个值→写法误报;把"袖带"读过去而无感→漏检。

所以本层的每一步都在"宁可漏掉,绝不误报"上下注:解析不干净就弃权(返回 `None`/`continue`)、点落区间判一致、写法归一后不报、拿不准的降级成 info 或"待确认"交人。**召回的缺口,明确让渡给 LLM 维度轴和人工抽查去补。**

分层定位(详尽版第 3.0 节):

- **Tier1 确定性**:`check_params_numeric.py`(数值一致)、`check_table_diff.py`(同构表 diff)、`check_residue.py`(模板残留)。规则可枚举、判定可复算、结论可签字定位。
- **Tier2 跨异构表对账**:`check_bom_crosswalk.py`。**对账逻辑本身是确定性的**,但它依赖上游(尤其 WI 散文由 LLM)抽成统一 schema;且"漏录"一类**诚实承认不是近零误报**,降级成 info。
- **真正的语义层(LLM)** 处理"测量精度 ±0.2℃ 在 35~42℃ 段 vs ±0.3℃ 全量程"这种带温度段/重复性歧义的判断——本层主动放弃,不碰。

## 何时用(何时必跑)

- 拿到一个型号转好的 MD 语料 + 抽好的参数长表后,做机械层基线扫描时(每个型号至少跑一遍残留扫描 + 数值一致)。
- 怀疑某参数(电流/温度/量程/防护/重量尺寸/电池容量/关机时间等核心参数)跨阶段、跨文件写了不同值 → `check_params_numeric.py`。
- 同一份 BOM/元器件清单在两阶段、两版本之间要查"差在哪"(仅A有/仅B有/某列值变了)→ `check_table_diff.py`。
- BOM、元器件清单、装配 WI 之间要核对用量/规格/图号是否对得上(尤其 WI 多工步求和)→ `check_bom_crosswalk.py`。
- DHF 是从老型号模板另存为改出来的,要查异类品类残留、异类型号残留、占位符未替换 → `check_residue.py`。
- 判断一条 finding 该不该归到确定性层:**带温度段/重复性的精度、分辨率,等效表述("防水"vs"IPX7"),需要理解上下文的矛盾 → 不归本层,交 LLM。**

### 步骤 1 — 先跑模板残留扫描(最便宜、最高频)

```
python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_residue.py" \
  "D:/AI_0415/03DHF/PT9L_MD" --product PT9L \
  --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-机械校验报告.csv"
```

**先按产品线配词库**(词库是穷举的,不配等于白扫):

- `--foreign 词1,词2` 追加异类品类词。内置 `DEFAULT_FOREIGN = 血压计,血压,袖带,耳机,雾化器,冲牙器,PC Link`。审体温计就该排斥冲牙器/雾化器的词;审冲牙器要把内置的"冲牙器"语境换成它该排斥的别线词。
- `--models 型号1,型号2` 追加异类型号。内置 `DEFAULT_FOREIGN_MODELS = PT3,PT5,PT9C,AG-633,BG5S,FDIR,T-Z1,sim`。
- `--allow-reuse PT5,PT3,...` 复用件白名单(默认 `PT5,PT3,T-Z1,Public,KD,PT1`)。**白名单里的型号命中只标"待确认(可能复用)"而非"中",交人判**——旧型号出现在新 DHF 可能是合法复用件(如沿用 PT5 传感器),机器不能凭出现就判错。

输出三类、四级严重度(排序键 `高=0/中=1/待确认=2/低=3`):异类品类(高,裸子串包含)、异类型号(中或待确认,带 `(?<![A-Za-z0-9])...(?![A-Za-z0-9])` 边界防 `PT3` 误命中 `PT35`)、占位符(低,正则 `X{3,}/待填/待定/TODO/○○/\bxxx\b/＿{3,}/_{4,}`,且排除含"年 月 日"的合规空栏)。脚本自动跳过 `_manifests/llm_wiki/__pycache__/dhf_audit_toolkit` 目录(避免自我命中)。

**判读:** 异类品类基本是错,直接进错误表;异类型号逐条看是残留还是复用件;占位符快速过一遍补填。

### 步骤 2 — 跑数值一致性(Tier1 核心,对 SSOT 长表)

```
python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_params_numeric.py" \
  "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-运行参数长表.csv" \
  --product PT9L \
  --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-数值冲突.csv"
```

管线:`canon()` 规范参数名(同义词归一,`动态电流/运行电流/工作功耗→工作电流`,带负向护栏:`整机重量/整机尺寸` 命中"箱/包装/运输/托盘"则弃权返回 `None`)→ 噪声过滤(剔除含"实测/水槽/号机/逐次/measured"的行;电池容量行剔"说明书/装箱"等)→ `signature()` 单位归一(℃/℉、A/mA/µA、mm/cm/in、s/分/时、g/kg、mAh)+ 五种形态解析(区间 `a~b`/容差 `a±b`/边界 `≤≥<>`/单点/特殊:防护取 `IPxx`、尺寸取排序后数值三元组、"最大42.9最小32"归一成区间)→ 按 `(canon, qualifier)` 双键分组(限定词如静态/动态/物温/体温,防把静态电流和动态电流混一组)→ `to_iv()` 签名转区间,**点落区间/容差内 = 一致不报**,组内 ≥2 个归一后仍不同的区间 = 真冲突。

**近零误报的体现(必须理解,别误以为它在漏):** `34-43` vs `34~43` 归一后都是 `[34,43]` → 同签名 → 不报;解析不干净 → 返回 `None` → `continue` 不进比对;**精度/分辨率(带温度段+重复性歧义)源码注释明确"确定性不可靠,移交 LLM,此处不做比对"**。

**看终端摘要:** `长表 N 行,可解析数值参数实例 M 个,规范参数组 K 个,确定性数值冲突 X 组`。PT9L 实测抓 0 组——**不是 PT9L 没冲突,是那批冲突不在 408 行长表里(抽漏了)**。这是已知的低召回边界,补召回靠 LLM,不要据此判定"无问题"。

### 步骤 3 — 同构表 diff(两版/两阶段同一份 BOM)

```
python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_table_diff.py" \
  "冻结版BOM.xlsx" "量产版BOM.xlsx" \
  --key 物料编码 --cols 品名,材质,规格,型号,封装形式,配比 \
  --labelA 冻结 --labelB 量产 \
  --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-BOM-diff.csv"
```

`--key`/`--cols`/`--header` 不给则自动探测(表头扫前 15 行找"物料编码/图号+品名"关键词;主键候选 `物料编码→物料编号→图号→料号` 子串包含;比对列取两表交集减主键减"序号"列)。原理是**按主键 key-join 而非按行号对齐**(行序漂移不影响),交集逐列比值,`norm` 折叠空白+全角空格后比,两边都空不报。`.xlsx` 用 `openpyxl(data_only=True)` 取公式计算值,`.xls` 用 `xlrd`。

输出三类:仅A有 / 仅B有 / 值不同(逐列给 A值 vs B值,可签字定位)。

### 步骤 4 — 跨异构表对账(Tier2,BOM↔清单↔WI)

先把各来源抽成**统一 6 列记录表**(BOM/清单确定性抽取;WI 散文由 LLM 抽成同 6 列),再:

```
python "D:/AI_0415/03DHF/PT9L_CHECK/dhf_audit_toolkit/check_bom_crosswalk.py" \
  "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-零件记录表.csv" \
  --out "D:/AI_0415/03DHF/PT9L_CHECK/PT9L-对账.csv"
```

原理:零件名两级归并(同义词词典 `SYN`,如 `螺钉=螺钉/螺丝/screw/自攻/机牙`;未命中走 `SequenceMatcher ratio≥0.8` 模糊归并)→ 中文数字+量词用量解析(`parse_qty`,"两颗"=2,量词限 `颗/个/件/根/pcs`)→ 按 `(canonical, 来源)` 聚合(**WI 多工步在此自动求和**)→ 跨来源核对:用量冲突(去重后 ≥2 值才报)、图号/规格冲突(≥2 来源有值、并集 ≥2 值、且**来源间交集为空**才报)。

**诚实标边界:** 这一步**不是近零误报**。"某零件只在部分来源出现"(漏录)被**降级为 info**写进 `...-info范围差异.csv`,标"人工看"——因为异构表范围天然不同(总装 ABOM 不含机芯件、WI 不列全部件),当冲突报绝大多数是误报。三个输出:`...-crosswalk.csv`(矩阵)、`对账.csv`(真冲突)、`...-info范围差异.csv`(漏录候选)。

### 步骤 5 — 汇入错误表 + 交自验证层

把四个脚本的冲突/命中(去掉 info 与"待确认"中机器拿不准的)汇入该型号错误总表(列名对齐 `assemble_incremental.py` 的 schema),每条带:出处文件 + 行号/主键/列 + 两侧原值。机械层每条都是可签字定位的,**但仍要走自验证层 `verify_findings.py` 的引文核验**(根目录 `D:\AI_0415\03DHF\verify_findings.py`),保证溯源闭环。

## 与其它层的衔接

- **上游(提取层)**:本层的天花板被提取层锁死。`check_params_numeric.py` 只能比对 SSOT 长表里有的参数;一个藏在 OLE/勾选框里没被抽出的参数,它永远抓不到。所以"机械层 0 冲突"≠"无问题",只能说"长表内无确定性冲突"。
- **下游(LLM 语义维度轴)**:本层主动弃权的(精度/分辨率温度段、等效表述、需上下文的矛盾、模糊归并漏并的跨来源冲突)全部留给 LLM 补召回。两层互补:确定性版近零误报但低召回,LLM 版高召回但需证伪,一起用才同时拿到 precision 和 recall(详尽版 2.5.5)。
- **双轴定位(详尽版 2.6)**:本层是子轴②(横向参数槽位 = `check_params_numeric.py`)和维度轴里 BOM 对账/版本漂移那几维的确定性内核。它**不覆盖**:有向承接走样(子轴①,需带"下游不得放宽"方向)、人名串号(子轴③)、"该有却没有"的缺失(子轴④)。
- **自验证层(`verify_findings.py`)的接缝**:机械层冲突的引文(出处原值)拿回语料 grep 应能命中。注意**缺失断言要特判**——`verify_findings.py` 用 `NEG` 关键词集(`无/未/缺/NEI/全文无...`)识别"全文无 X"这类否定断言,否则会把真缺失误判成"可疑"(初版 41 条被误杀,加 NEG 后降到 5 条)。本层基本不产缺失断言(那是子轴④),但汇错误表时别把别层的缺失断言混进来不做特判。

## 边界与踩坑(诚实标,不许粉饰)

- **Tier1 数值层是低召回的**:它主动放弃所有拿不准的,召回率本质不可知,只能用 `parsed/总行数` 间接看健康度。真实漏报靠 LLM 和人工暴露。**不能用"0 冲突"下"无问题"结论。**
- **跨异构表对账非近零误报**:依赖上游抽取质量(尤其 WI 的 LLM 抽取,garbage in garbage out);模糊归并 `0.8` 阈值对中文短词偏严,两字零件名易算不到 0.8 → 同件被拆 → 漏报;`parse_qty` 只认 `颗/个/件/根/pcs`,"两套/两组"抓不到;用量冲突不设业务容差(10 vs 9 报,余量规则也按冲突报,需人复核)。
- **同构表 diff 的盲区**:只比第一个 sheet;主键探测可能选错列(有"物料编码"+"旧物料编码"时用 `--key` 指定);重复主键只保留第一条(看到 dup 非零要警惕"一料多处"结果不完整);**列名重命名是盲区**(B 版把"材质"改叫"材料"→该列不在交集→整列静默漏比,需 `--cols` 兜)。
- **残留扫描只查"形"不查"义"**:能发现"血压计"三个字,但发现不了"冲牙器工作压力数值误填进体温计参数表"这种值错(数字看着正常);词库穷举,漏配词等于看不见;`PC Link` 含空格靠裸 `in` 且品类词分支无 `IGNORECASE`,写成 `PCLink`/`pc link` 会漏;复用件白名单是型号粒度(同文件里合法 PT5 复用件 + 忘改 PT5 残留都只标"待确认",仍要人逐条看);逐行扫描,残留词被换行拆开抓不到。
- **平台/依赖**:脚本在 Windows + Python 3 跑;`check_table_diff.py` 需 `openpyxl`(.xlsx)/`xlrd`(.xls),缺库会在 import 时炸,环境得装对版本。所有脚本已 `sys.stdout.reconfigure(encoding="utf-8")` 防 GBK 控制台崩;输出 CSV 均 `utf-8-sig`(Excel 双击不乱码)。
- **字段名/schema 纪律**:汇错误表时机器解析字段保持 ASCII/约定字面量(严重度 `critical/major/minor`、列名跨型号一致),值可中文。词库(`CANON`/`SYN`/`DEFAULT_FOREIGN`/`DEFAULT_FOREIGN_MODELS`)是手工维护的、产品相关,**每条新产线先配词库再跑**,否则形同虚设。
