# Self-Verification Skill（自验证层）

## 目的（解决什么 / 朴素做法为什么不行）

前面几层（转换 / 提取 / 检查）解决的是"怎么把 finding **找出来**"。但找出来不等于可信。LLM agent 在跨文件做一致性审核时有四类系统性失真，这一层就是专门兜它们的：

1. **编造证据**——声称"原文写了 X",但语料里根本没这句。引文一假,整条 finding 地基塌掉,拿着伪原文去找工程师对质,审核公信力归零。
2. **过度自信的孤立断言**——一条 finding 听起来言之凿凿,但没有第二双眼睛挑战它;生成它的 agent 有确认偏误,带着"我要找问题"的目标读文档,倾向把任何差异都解读成错误。
3. **跨型号重复误报**——PT9L 上 PM 拍过"焊点数 vs 线数不算矛盾",到 PT7/PT9S 新一轮 agent 没记忆,又把同样差异报成矛盾。每次让 PM 重新解释一遍,是巨大浪费、消磨信任。
4. **沉默的漏做**——某维度整章没查、某文件夹被跳过、证据核验忘了跑、美国法规基线没用上。这些不报错,agent 也不会主动说"我没做 X"。跨型号复用方法论时最容易这样漂移。

**朴素做法为什么不行:**

- **让人逐条核引文**——一份 DHF 转出的 MD 语料动辄几十文件、上百万字,一轮审核产出几十上百条 finding,人眼搜中文长句极易漏(标点 / 全角半角 / 行号前缀都让"看起来一样"的句子搜不到),几十条就是大半天。
- **再叫一次 LLM 来核验 LLM**——等于让嫌疑人自证清白,两个模型可能犯一样的错甚至互相圆谎。
- **把误报反馈拿去微调模型**——代价高、不可解释、修一个误报可能引入新偏差,机构记忆埋进权重里没人能维护。

**本层的统一设计哲学:用便宜、确定、可重跑、宁可低召回也要近零误报的检查,去兜底昂贵、随机、可能过度自信的 LLM 判断。** 这一层自己必须是确定性的——纯字符串 / 计数运算,无浮点、无模型、无随机,同样的产物跑一百遍给一百次相同结论。否则"验证"二字无从谈起。

## 何时用

- 检查层已产出错误总表 / 参数长表(SSOT),**在交 PM 裁决、出 HTML 裁决版报告之前**。
- 跨型号复用方法论时(从 PT9L 迁到 PT7 / PT9S / M10),开新型号收尾必跑系统自检,防漂移漏做。
- 怀疑某条 finding 的引文可能是 agent 编的、或某条结论"引文真但逻辑站不住"时。
- 这一层**不**负责判"值本身对不对"——那是工程师 / PM 的工程判断(见裁决库第 5 条 `一致性;值;错 → 提醒`:`一致性≠正确性`)。本层只判"agent 有没有编造、对不对得上、该做的做没做"。

## 强制工作流（编号步骤，不许跳步）

### 1. 先加载通用工作方法 skill
- `D:/AI_0415/03DHF/skill/SKILL.md`(喵信号 / 文件工具对照 / 做事纪律)。

### 2. 跑证据核验 verify_findings.py（引文回查全语料 grep）
```
python D:\AI_0415\03DHF\verify_findings.py <错误总表.csv> <MD语料根目录> <输出证据核验.csv>
# 例(PT9L):
python D:\AI_0415\03DHF\verify_findings.py D:\AI_0415\03DHF\PT9L_CHECK\PT9L-错误总表.csv D:\AI_0415\03DHF\PT9L_MD D:\AI_0415\03DHF\PT9L_CHECK\PT9L-证据核验.csv
```
脚本内部算法(读 `verify_findings.py` 对照):
- `norm()`:一条正则抹掉空白 / 全角空格 / 竖线 / 各种引号括号,**只删噪声、保留 CJK 汉字、字母数字、勾选框 ■□、法规号点号(如 `880.2910`)**。语料和引文都过同一个 `norm`,在去噪空间比对。
- `extract_quotes()`:用 `QUOTE_RE`(5 个引号正则)从证据列抽出引文,长度下限 4 字(撇号类 6 字)、上限 200 字;`norm` 后不足 4 字丢弃;用正则识别出**纯文件指针**(如 `'PT9L-设计输入.md'`)丢弃(那是指文件不是引原文)。
- `find_quote()`:整段命中——`nq in ntxt` 一字不差(去噪后),最强证据。
- `find_partial()`:整段没中时,取**首 12 / 正中 12 / 尾 12** 三个字窗口,任一命中即"基本真实,只是行号 / 标点漂移";短于 12 字不做部分匹配。
- `is_absence()`:用 24 词 `NEG` 集(`无/未/缺/缺失/未出现/未承接/未锚定/留空/应含/本应/查无…`)外加严重度 `=NEI` 识别**缺失类断言**——这种"证据"是否定断言,无法正向 grep,**必须先摘出来,否则缺失类会被冤判成可疑**。

**五分类裁决(verdict,字面照抄,勿改字):**

| verdict | 含义 | 处置 |
|---|---|---|
| `有据` | 引文整段在真实语料命中 | 可信,无需复核 |
| `有据(部分)` | 整段没中但长片段命中(行号 / 标点漂移),或缺失类的正向引文有据 | 基本可信 |
| `缺失断言` | 断言"某项缺失",无法正向 grep,须另用"确认缺失"流程核 | 转人工 / 另一套核法 |
| `可疑` | 声称原文写了 X,但全语料完全找不到 | **人工复核重点(可能编造 / 严重改写)** |
| `无引文` | 纯结构 / 汇总判断,没有可 grep 的原文引文 | 另行人工 |

跑完看控制台:它会把**所有"可疑"条目单独打印**(带严重度 / 轴 / 阶段 / 引文前 75 字)。**优先只盯"可疑"那几条**——那是最可能编造的。`有据 + 有据(部分)` 合计即"有据率"。
> 跨文件夹标记:命中文件的阶段号若与 finding 声明的阶段号不一致,标 `跨文件夹命中=是`——这往往正是跨文件矛盾的物证。

### 3. 对抗证伪 CoVe（派独立反方 agent 反驳，约毙 1/4）
证据核验只管"引文真不真",管不了"引文真、逻辑却站不住"(如:两段原文都真,但判二者矛盾,实则说的不是一回事——`4 焊点 vs 3 线`本就不矛盾)。这类需要 CoVe。**核心是角色分离,不是让生成者自查**:
1. 取 finding 与**完整上下文**(原文引文、声称的矛盾点、涉及的两个/多个文件夹)。
2. 构造**反方提示**:让验证 agent 站在"**这条 finding 是错的,请你证明它站不住**"的立场,而非中立复查(中立复查会退化成附和)。
3. **强制独立取证**:验证 agent 必须自己回原文读上下文,不能只看生成 agent 给的摘要。
4. 分情况裁决:反驳成立 → **毙掉**;反驳不成立 → 保留(经正反两轮置信度更高);部分对 → **降级 / 缩小范围**。
5. 被毙掉的、反复出现的反驳理由 → 沉淀进裁决库(步骤 4),下次确定性拦截,不再烧 token。

**约毙 1/4 是健康区间**:毙太少(<5%)= 对抗在走过场;毙太多(>50%)= 生成层质量太差,应回去修生成层而非靠验证层兜。
> 边界:CoVe 也是 LLM,可能反驳过头把真错误毙掉。所以**它的产出不是终判**,被毙的仍进 PM 裁决环节,"误报"是 PM 拍板沉淀的。对"应该有 X 却没有"的缺失类,反方很难"证明它没缺失",效果有限,仍依赖人工。

### 4. 维护裁决库 _adjudications.csv（PM 误报固化 + 关键词全含撞库）
裁决库是极简 CSV(不是模型、不是嵌入库),五列 ASCII 语义固定:
```
关键词(全含;分隔),裁决,说明,来源型号
```
- `裁决` 取值:`误报`(参与撞库、确定性拦截)/ `提醒`(只写给人看的方法论备忘,**不参与撞库**——脚本里 `if a["裁决"]=="误报"` 硬过滤掉)。
- 关键词用分号分隔,撞库是**全含 AND**:`all(k in text(r) for k in kws)`,一条 finding 文本(描述+类型+证据拼起来)**同时含全部关键词**才命中。用 AND 不用 OR,是因为单个词太宽("矛盾"任何一轮都出现几十次);要 2–3 个词同现才能把"误报的特定情形"刻画得足够窄。
- 撞库后**只当候选提醒、绝不自动删**(关键词匹配偏松,常是顺带提及 / 不同问题)。删不删的终判权留给人。

当前 5 条规则(各拦什么):

| 关键词(全含) | 裁决 | 拦的是什么 |
|---|---|---|
| `传感器;焊点;矛盾` | 误报 | 焊点数 vs 线数不是矛盾;真错是装配说明写"四根线" |
| `静音;收窄` | 误报 | 静音是拨动开关(2 键+1 拨动),无功能收窄 |
| `欧盟;裁剪;错` | 误报 | 仅美国项目正确裁掉欧盟 / EN / CE 是对的;反向拿 EN 当美国基准才是真错 |
| `EN ISO;裁剪;缺` | 误报 | 同上,US-only 裁掉 EN 协调版是正确的,别当缺失报 |
| `一致性;值;错` | 提醒 | 一致性≠正确性;值本身对不对要工程师 / PM 拍 |

PM 新拍一个误报 → **追加一行**(2–3 个能共同锁定具体情形的词;别写单个宽泛词,会污染),写清 `说明` 和 `来源型号`。

### 5. 跑系统自检 audit_self_check.py（八项元检查，防漏做）
```
python D:\AI_0415\03DHF\audit_self_check.py <型号>
# 例:
python D:\AI_0415\03DHF\audit_self_check.py PT9L
```
脚本用 `CFG` 字典为每个型号(PT7/PT9L/PT9S/M10)配好目录 / 文件名 / 列名(PT9S 列名不同;M10 用中国法规正则)。八项:

1. **① 工具产物齐全**——错误总表 / 参数长表(SSOT) / 证据核验.csv / 增量审核报告.md 在不在,glob 找 HTML 裁决版。任一缺 → `FAIL`(这步可能忘了跑)。
2. **② 阶段覆盖**——统计 finding 阶段号,算 `gaps`(阶段号跳空)。中间缺一段 → `WARN`(确认合并阶段还是漏审)。
3. **③ 字段完整**——证据列 / 建议列 / 责任人列有没有空。空 → `WARN`(没法落地修)。
4. **④ 七维度覆盖**——`DIM` 九维(数值一致 / 可追溯断链 / 不收窄 / 矛盾措辞 / BOM 对账 / 版本漂移 / 角色串联 / 模板残留 / 法规完备)各配特征词,**某维 0 条 → `FAIL`**(这维可能整个忘了查)。
5. **⑤ 已裁决误报重现**——即步骤 4 的裁决库全含撞库,命中 → `WARN` 候选。
6. **⑥ 法规基线锚定**——正则 `880\.2910|UDI|807|801|510\(?k|SDV|FLL|ASTM|80601` 数美国强制法规命中数;0 条 → `FAIL`(目标市场基线没用上)。M10 走中国法规正则(`GB 9706|YY/T|NMPA|产品技术要求|14971…`)。
7. **⑦ 证据核验摘要**——读步骤 2 产出的证据核验.csv,汇总五分类,把"可疑"逐条列出 → `WARN`;若该 csv 不存在 → `WARN`(未跑证据核验)。
8. **⑧ 跨型号系统病对照**——`SYS` 固化三大系统病(模板残留他型号 / 美国强制法规缺 / 参数全链放宽收窄),**新型号某类 0 条 → `FAIL`**(前两型号都有,新型号没查到 = 疑漏查)。

结论判定:有 `FAIL` → `❗ 有必查项,先处理`;只有 `WARN` → `⚠️ 基本通过,看提醒项`;全清 → `✅ 全部通过`。同时写出 `<型号>-自检报告.md` 留痕(控制台 `✅⚠️❗` 即时扫读,.md 跨型号对照)。
> ④⑥⑧ 用"命中 0 条就 FAIL"的粗判据,**只能证伪"整块没做",不能证明"做对 / 做全"**。某维有 5 条只说明查了,不保证 5 条全对、更不保证没漏第 6 个。自检是"流程完整性体检",不是"质量评分"。

### 6. 收口
- 把"可疑"清单(步骤 2)+ CoVe 毙掉的 + 撞库候选(步骤 4/5)+ 自检 `FAIL/WARN`(步骤 5)汇成一张**人工复核单**交 PM。
- 确定性层只做拦截 / 提醒 / 候选,**最终删不删、改不改,终判权在 PM**。PM 拍出的新误报回流步骤 4 沉淀。

## 与其它层的衔接

- **上游(检查层)**:本层的输入全部来自检查层的错误总表 / 参数长表 / 增量报告。检查层(尤其 Tier1 确定性数值检查)走"近零误报、宁可低召回";本层接着用同一哲学做二次确定性兜底。
- **上游(转换 / 提取层)**:证据核验 grep 的对账面是转换后的 MD 语料。**本层的前置假设是转换层已验证**——若转换丢字 / 串行,真引文会被冤判"可疑"。转换层的 `loss_flags` / `manual_review_required` 是这层判"可疑"时要先排除的干扰源。
- **下游(编排 / 交互裁决输出层)**:本层产出的"可疑 / 毙 / 候选 / FAIL"喂给 HTML 裁决版报告,PM 在那里逐条拍板;PM 的裁决再回流裁决库,形成闭环。

## 边界与踩坑（诚实标注）

- **证据核验只验"引文存不存在",不验"finding 对不对"**。引文真实 ≠ 结论正确(裁决库第 5 条已固化此原则)。
- **缺失断言是真正的盲区**。"全文未出现 X"无法 grep 证实也无法证伪,只能判 `缺失断言` 挂起,转人工 / 另用"确认缺失"流程。这是设计上的诚实,不是 bug。
- **窗口匹配有罕见假命中**。12 字窗口理论上可能在无关文档凑巧撞上,把改写过头的引文误判 `有据(部分)`——这是为压低误报付的代价(宁可放过不冤枉),漏网的下一层 CoVe 有第二次拦截。
- **PT9L 实证数据**:NEG 关键词早期不全,缺失类被大面积冤判,初版 **41 条假可疑**;补全 NEG(24 词 + NEI)后**降到 5 条**。证据有据率从初版约 **18% 提升到 84%**——提升主因不是 agent 变诚实,而是核验器学会了正确分类(把漂移真引文从可疑捞回有据部分、把缺失类摘进缺失断言)。
- **CoVe 也是 LLM,会反驳过头**;成本高(每条都独立回原文重读),正是裁决库存在的理由——把反复结论固化成确定性规则省 token。
- **裁决库关键词撞库天生偏松**,会有假候选(常是顺带提及 / 不同问题),定位是"提醒人去看",**当自动删除用就会出事**。规则靠人手维护会过时(新型号真去掉了静音功能,老规则反而掩盖真问题)——"提醒非删除"的设计也是对过时规则的兜底。
- **检查层的已知低召回要记住,不要在自验证里假装它不存在**:Tier1 数值检查在 PT9L 抓 0 组冲突,不是没冲突,是冲突不在 SSOT 长表里(抽漏了);**跨异构表对账是低召回机制,不是近零误报**(它和同构表 diff 不同)。自验证不能把"检查层没报"当成"没问题"。
- **平台 / 编码**:脚本首行 `sys.stdout.reconfigure(encoding="utf-8")`,所有 CSV 用 `utf-8-sig` 读写(Windows 中文环境防乱码)。机器解析的字段名 / verdict 全 ASCII 或固定中文字面量,**勿改字**(下游按固定字符串读)。
