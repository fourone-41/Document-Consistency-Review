# Skill: 2D 工程图纸读图

## 目的

从 2D 工程图纸（PDF）中**准确、无遗漏、无误读**地提取尺寸、公差、配合关系、工艺要求等信息，并明确每条结论的可信度等级，避免把"图上没有的信息"凭印象写出来。

本 Skill 与 `SKILL_3D_Model_Analysis.md`、`SKILL_3D_Section_Analysis.md` 三件套配合使用：

- 2D 图：标题栏、技术要求文字、尺寸+公差、配合声明
- 3D 模型：完整三维形状、装配相对位置、bbox
- 3D 剖面：内部结构、壁厚、配合间隙

---

## 核心原则

### 0. 2D 图是 3D 的投影（最底层认知）

读 2D 图之前先在心里装上这几条：

1. 2D 图上的每一条线，都是某个视角下把 3D 模型上"可见边"做 HLR 投影得到的。**两条线在 2D 图上相交，不代表这两个特征在 3D 里有接触**——深度方向上可能相差很远。
2. 圆视图上**从中心放射出的细实线不一定是"从圆心出发的半径"**。它可能是某条结构实体边（例如扭转卡扣的受力边、键齿的侧边）在投影平面内的**延伸线**；该实体边本身只存在于某段半径范围内，延伸到圆心仅是几何巧合。
3. **A-A / B-B 等截面标识线一定有明确的定位规则**——要么沿着一条具体的实体边，要么垂直于某条边的中点，除非图上有另外说明。读角度尺寸前先确认截面/中心线锁在哪条实体边上。
4. **任何"线条密集、不容易看清"的区域都不能绕开**（不限于中心）——这些地方往往就是核心功能结构（扭转卡扣、键齿、限位凸台、多层叠套结构）。处理顺序如下：
   - **手段 1（首选）**：先对该区域做**极致放大的 2D 局部切图**——DPI 不够就升到 600/1200；再不够就裁出 200×200 像素级的小窗口逐条数线、逐条判断线型（细实线 / 细点画线 / 粗实线 / 虚线）。大多数密集区在充分放大后是可以看清的。
   - **手段 2**：**只有**当 2D 充分放大后仍然分不清线条归属（比如多条结构线重叠、线宽相近、视角压缩导致不同深度的线在投影里重合），才转 3D HLR 投影对照。
   - **判定规则**：3D 投影是辅助手段，不是第一手段。第一手段是把 2D 读到极限。
5. 圆周上看似"均布小齿"的短矩形特征，**在投影里也可能是倾斜凹槽的两条长边**（60°/120° 斜向）。需要先确认这些特征是径向的还是斜向的，再谈"均布数"。
6. **3D HLR 投影使用前必须方位校准**。投影的 `view_dir` 和 `up_dir` 组合会产生多达 8 种不同画面方位，但 2D 图所选方位只有一种。**方位校准的做法**：在 2D 图上挑**至少 2 个非对称、易识别**的特征作为基准（例如"模穴号 Y 的字符位置"、"某条分型线点画线的倾角"、"某个编号的字母方向"），生成 3D 投影后逐一比对这些特征的角位置；只有**全部基准都对齐**才能用此投影读尺寸。单一基准可能偶然对上其他方位，**必须交叉验证**。

### 信息边界

**2D 图能给出（事实，A 级可信）：**


| 信息类型          | 来源         | 用途                                                |
| ------------- | ---------- | ------------------------------------------------- |
| 标题栏字段         | 右下表格       | 零件名/材料/比例/默认公差/版本                                 |
| 配合关系（哪两个零件配合） | 技术要求第 1 条  | 装配关系最权威来源                                         |
| 数字尺寸 + 公差     | 编号引出线      | 直径/长度/角度/厚度                                       |
| 重点尺寸标识        | 尺寸下方"重点尺寸" | QC 检验项                                            |
| 注塑工艺要求        | 技术要求条目     | 缩水、断差、毛刺等                                         |
| 颜色 PANTONE 号  | 印刷区注释      | 印刷色                                               |
| 几何角度（°数值本身）   | ° 标注       | 数字本身 A 级；**含义必须做引出线追踪 + 3D 投影验证**（见 Step 6.2-bis） |


**2D 图能间接给出（需识图，B 级可信）：**


| 信息类型             | 方法                | 局限               |
| ---------------- | ----------------- | ---------------- |
| 视图类型（俯/侧/剖/局部放大） | 看图框和"截面 X-X"标识    | 局部放大需对应主图位置      |
| 周向均布特征数量         | 角度反推（360°/θ）+ 现场数 | 仅当θ均匀时有效         |
| 同类特征分组           | 小写字母 a/b/c...     | 同字母在多视图对应同特征     |
| 配合间隙（粗略）         | 两零件直径相减           | 仅能说"留有间隙"，不知接触模式 |


**2D 图不能给出（必查 3D，C 级或不可获取）：**


| 信息类型        | 替代来源                 |
| ----------- | -------------------- |
| 复杂三维形状细节    | 3D 模型（带"符合3D图纸"标识必查） |
| 接触模式（点/线/面） | 3D 剖面                |
| 卡扣实际形态与变形方向 | 3D 模型 + 力学分析         |
| 装配后相对位置     | 3D 装配体               |
| 运动行程        | 装配图或动画，单零件图不可推断      |
| 触发条件、解锁动作   | 工程师确认或专利说明书          |

## 强制工作流（每张图必跑）

```
Step 1  检查 PDF→PNG 转换 DPI
Step 2  分块切图（6 或 9 块）
Step 3  读标题栏
Step 4  完整读技术要求（A 级信息！）
Step 5  逐编号扫描尺寸（按 ①②③… 顺序）
Step 6  跑 6 项自动检查
Step 7  对所有"看似 Φ" 项做视觉确认
Step 8  对所有"与 X 配合" 跑交叉验证
Step 9  输出尺寸表，标注 A/B/C 可信度
```

### Step 1：DPI 检查

**强制 ≥ 300 DPI**。200 DPI 下圆圈编号 ① 与希腊字母 Φ 视觉极易混淆，已知翻车场景。

```bash
# 用 pdf-vision skill 的脚本
python -c "import sys; sys.path.insert(0, r'C:\Users\<user>\.cursor\skills\pdf-vision\scripts'); from pdf_to_images import convert_pdf; convert_pdf('xxx.pdf', None, 300)"
```

注意 PowerShell 不能传空字符串占位参数，必须用 `None`。

### Step 2：分块切图

A3 图纸 300 DPI 下约 3508×2481 px。一次读全图细节会丢失，必须分块。

```python
from PIL import Image
img = Image.open('page_001.png')
W, H = img.size
cols, rows = 3, 2          # 6 块（推荐复杂图）；简单图 2×2 即可
overlap = 100               # 块间重叠，避免标注被切断
cw, ch = W // cols, H // rows
for r in range(rows):
    for c in range(cols):
        x0 = max(0, c*cw - overlap)
        y0 = max(0, r*ch - overlap)
        x1 = min(W, (c+1)*cw + overlap)
        y1 = min(H, (r+1)*ch + overlap)
        img.crop((x0,y0,x1,y1)).save(f'crop_r{r}c{c}.png')
```

每块逐个用 `Read` 工具调用 vision 阅读。

### Step 3：标题栏

标题栏稳定字段（A3E 图纸样式）：


| 字段           | 必读                       |
| ------------ | ------------------------ |
| Drawing NO.  | ✅ 图号                     |
| Part name    | ✅ **中文零件名（替代 P0X 代号使用）** |
| Pro material | ✅ 材料                     |
| Surf dispose | ✅ 表面处理                   |
| Scale        | ✅ **视图比例（决定尺寸读取的实际值）**   |
| Tolerance    | ✅ 默认公差表（.X / .XX / .XX°） |
| Edition      | ✅ 版本                     |
| Model NO.    | ✅ 项目号                    |


### Step 4：技术要求（最易忽略也最重要）

技术要求**第 1 条**几乎总是写"与 XX 配合无干涉/转动有卡顿/...."，是装配关系**最权威的证据来源**——优先于任何从 3D 推测的配合判断。

**逐条完整读，不要跳过**。常见关键字：

- "与 ... 配合无干涉"：装配关系声明
- "运动流畅"：有相对运动（但未指定运动量）
- "转动时有卡顿感"：旋转配合且有齿状阻尼（强提示）
- "断差不超过 X mm"：装配间隙容差
- "无晃动 / 无间隙"：紧配合
- "结构符合 3D 图纸"：2D 不全，必查 3D
- "不大于 0.1mm 的圆角/毛刺"：默认工艺要求
- "GB/T 14486、MT2 级"：默认公差等级

### Step 5：逐编号扫描尺寸

对每张图按 `①②③…` 顺序，每个编号必须捕获 5 项：


| 字段      | 例                              |
| ------- | ------------------------------ |
| 编号      | ⑤                              |
| 视图位置    | A-A 截面下方                       |
| 几何符号    | Φ / R / SΦ / SR / C / 无        |
| 前缀      | 数量类型字母-（如 `2c-`、`4f-`）         |
| 数值 + 公差 | 17.5±0.1 / 1.5⁰⁻⁰·² / 60.00°   |
| 注释      | （小端）/（大端）/（与 P05 轴孔配合定位）/ 重点尺寸 |


**禁止简化的事项：**

1. **公差形式**：⁺⁰·¹⁻⁰ 不能写成 ±0.1（前者只能向正，后者允许向负）
2. **前缀**：`2c-3.9` 不能写成 `3.9`
3. **括号注释**：必须**逐字保留**，不能复述
4. **几何符号**：Φ 不能丢，但**也不能凭空加**（关键在 Step 7）

### Step 6：6 项自动检查

#### 6.1 编号连续性

```python
def check_numbering(drawing_id, found_numbers):
    nums = sorted(set(found_numbers))
    if not nums:
        return
    expected = list(range(1, max(nums) + 1))
    missing = [n for n in expected if n not in nums]
    counts = {n: found_numbers.count(n) for n in nums}
    duplicated = [n for n, c in counts.items() if c > 1]
    if missing:
        print(f"⚠️ {drawing_id} 缺失编号: {missing} —— 必须回去重读")
    if duplicated:
        print(f"⚠️ {drawing_id} 重复编号: {duplicated} —— 确认是同尺寸多视图引出还是真错")
```

**缺号是错误的最强提示**，必须回去重读对应区域。

#### 6.2 角度反推均布数（仅为候选假设，不能直接采用）

对每个角度尺寸 θ 可先做一次快速整除：

```python
def check_angle(theta):
    if 360 % theta == 0:
        n = 360 // theta
        print(f"角度 {theta}° → 可能是 {n} 个均布特征间距（待验证）")
```

**360°/θ 整除只是"候选"，不是结论**。必须用 Step 6.2-bis 在 3D 投影上核验后才能定性。

##### 6.2-bis 3D 投影方位校准（强制前置，不可跳过）

**3D HLR 投影在使用前必须校准方位**，否则看起来结构"都在"，但整张图相对 2D 图旋转或镜像了，导致所有角度读错。具体流程：

1. **认识坐标映射陷阱**：`gp_Ax2(origin, N_direction, Vx_direction)` 中：
   - 画面 x 方向 = Vx
   - 画面 y 方向 = **N × Vx**（叉积，不是 Vx 本身也不是自动的"up"）
   - 仅改 `view_dir` 而把 `Vx` 留作 `(0,0,1)`，画面 y 方向会跟着翻转、旋转，**画面方位和"直觉"（+Z 朝上）经常不一致**。

2. **挑 2 个以上非对称基准特征做校准**。单一基准经常碰巧对上错误方位（例如梯形齿是 4 次对称的，4 种方位都能"对上"）。推荐同时用：
   - 模穴号字母（Y / A / B / N 等，非对称字符）
   - 分型线 / 中心线点画线的倾角
   - 编号圆圈（①②③）的位置
   - 非对称凸台、不对称扁口

3. **写代码直接定位 3D 中基准特征的坐标**：扫描短直线段（`length ∈ [0.2, 3]` mm）且位于合理半径的边，聚合它们在 Y 平面上的位置，识别字母所在的**端面 Y 坐标**和**径向方位角**。**不要用眼睛估算 3D 投影里字母位置**，字体渲染经常扭曲或被其他线覆盖。

4. **校准合格标准**：3D 投影中**至少 2 个基准**的方位角与 2D 图对应位置角度差 ≤ 5°。任一基准差 > 10° 就必须改 `Vx`、`view_dir` 重算，不能"感觉差不多"。

**P03 方位校准实例（本 Skill 另一重大翻车）**：
```
错误版：view=(0,1,0), Vx=(0,0,1)
  ├── 梯形齿在画面 3/9 点（3D +Z 被映射到画面 x 轴）
  ├── 模穴号 Y 字母在画面 12 点（3D +X 被映射到画面 y 轴）
  └── 2D 图里梯形齿在 12/6 点、Y 在 3 点 → 整张图旋转了 90°
       → 用这张投影读 24° 时找不到匹配结构边（而 2D 图上明明有 24° 标注）

校正版：view=(0,-1,0), Vx=(1,0,0)
  ├── 画面 x = Vx = (1,0,0) = 3D +X  → Y 字母在 3 点 ✓
  ├── 画面 y = (0,-1,0) × (1,0,0) = (0,0,1) = 3D +Z  → 梯形齿在 12/6 点 ✓
  └── 校正后 R≤5 中心区域立刻扫到 6 条端点方向 ±24° 的边
       (扭转卡扣 C 形叶片外缘弧段的端点连线)
```

配套代码思路：`cadquery` + `HLRBRep_Algo`；扫描并统计 `gp_Ax2` 八种组合（`view` 两方向 × `Vx` 四方向）下基准特征的画面位置，和 2D 图对照后锁定唯一方位。

#### 6.2-ter 引出线全程追踪 + 3D 投影交叉验证（强制，不可跳过）

**背景**：2D 图是 3D 模型在某视角下的线条投影。一张圆视图上从中心区域放射出的细实线，**不一定是"从圆心发出的半径"**；它可能是**某条实体结构边的延伸线**，该结构边本身只存在于某一半径范围内（如内圈 R=2 ~ R=4），延伸方向恰好指向圆心。把这种延伸线误认为"半径引出线"是常见严重误读。

**强制做法（对每个角度尺寸）**：

1. **追踪两条尺寸界线在零件体上的真实起点**
  - 界线的"靠圆心端"**是否真的落在圆心**，还是落在某条**结构粗实线**上？
  - 界线穿过零件体时的**线型连续性**是否中断（中断 = 界线外的部分是虚拟延伸，不代表实体边）
  - 若界线末端有箭头、端点符号、引出圆点，把它们标出
2. **生成该视角的 3D HLR 投影**
  - 用 `HLRBRep_Algo` 以 2D 图同向投影，用 `OutLineVCompound + VCompound + Rg1LineVCompound` 还原可见边
  - 和 2D 图等比叠放或并排对照，逐一核对两张图上每条线的对应关系
3. **遍历投影中的所有直线边，按与基准方向夹角分 bin**
  - 如果 2D 图上有 θ°，查 3D 投影里**是否存在**方向为 θ° 的直线段
  - 若**不存在**，说明 θ° 不是"某单一直线边相对基准的夹角"，而是其他含义（扇形张角 / 两组径向边的差 / 圆弧圆心角 / 键相位角等），不能套 360°/θ
4. **只要一条验证失败，就必须升级处理**
  - 如果 3D 上没找到对应边 → 把该尺寸标为"**含义待工程师确认**"
  - 如果 3D 上边的数量和 360°/θ 不符 → 特征不是均布，禁止写"n 个均布"

**反例（P03 ④ 24°，本 Skill 重大翻车案例）**：

```
V1：24° 是 P01-P03 旋转锁定角度           ← 错：把图纸几何当运动量
V2：24° 是"内圈 15 齿均布"的齿间距           ← 错：圆周上根本没有 15 个均布特征
V3：24° 是"15 对齿"的对中心间距            ← 错：把两条紧邻的平行凹槽边看成"一对齿"
    （凹槽本身还是倾斜的，不是径向）
真相：24° 的上方斜线不是"从圆心出发"的半径，而是
      中心扭转卡扣某条受力边的延伸线；该受力边只
      存在于 R≈2~4 范围内。24° 是该受力边与水平
      B-B 基准的角度，或两条受力边之间的夹角；
      3D 投影里 R<8 的直线边没有任何一条方向是 24°，
      数值化证据推翻了 V1/V2/V3 的所有假设。
```

**教训**：

- **没做 3D 投影对照之前，360°/θ 整除只是"可能性提示"，不是事实**
- **引出线的起点必须逐条核实**，不能默认它从圆心出发
- **圆视图上看似"均布"的密集小特征，先要确认它们是径向的还是倾斜的**（倾斜凹槽在投影上也会呈短矩形，容易与径向齿混淆）

##### 6.2-quater 运动量 vs 几何量

**重要**：即便 θ 的几何含义已确认（例如齿间距、位置角），也**不可**直接写"θ 是解锁角/旋转行程"。运动行程必须来自技术要求、装配图或工程师确认。

#### 6.3 前缀完整性

```python
import re
PATTERN = re.compile(r'[①-⑳]\s*(?P<prefix>\d+[a-z]-)?\s*(?P<sym>Φ|R|SΦ|SR|C)?\s*(?P<val>[\d\.]+)')

def parse_dimension(text):
    m = PATTERN.search(text)
    if not m:
        return None
    return {
        'prefix': m.group('prefix'),  # 如 '2c-'，可能为 None
        'symbol': m.group('sym'),      # 如 'Φ'，可能为 None
        'value':  m.group('val')
    }
```

**任何编号后到数值之间的字符都必须保留**，特别是 `nx-` / `字母-` 前缀。

#### 6.4 公差形式完整性


| 原始形式      | 不允许简化为    | 原因                 |
| --------- | --------- | ------------------ |
| ⁺ᵃ⁻ᵇ（不对称） | ±max(a,b) | 偏差范围不同             |
| ±0.1      | 0.1       | 公差信息丢失             |
| 0⁻ᵃ（单边负）  | ±a/2      | 中值偏移               |
| ⁺ᵇ⁰（单边正）  | ±b/2      | 中值偏移               |
| 无公差       | 默认 ±0     | 应取自标题栏 Tolerance 表 |


#### 6.5 配合关系交叉验证

```python
def check_mating(parts):
    # parts 是 {part_id: {'mates': [其他零件id], 'dims': {编号: 尺寸值}}}
    issues = []
    for a, info in parts.items():
        for b in info['mates']:
            if a not in parts.get(b, {}).get('mates', []):
                issues.append(f"{a} 声明与 {b} 配合，但 {b} 未声明与 {a} 配合")
    return issues
```

对配合直径（如 P02 ⑲Φ40.95 ↔ P07 ⑤Φ40.2），**自动算间隙**：

- 单边间隙 = (孔径 − 轴径) / 2
- 间隙在 0.025~0.5mm 间为合理装配；过大或过小要标记疑问

#### 6.6 ① ↔ Φ 视觉确认

对所有"看似 Φ + 数值"的标注：


| 检查项     | "可能不是 Φ" 信号                           |
| ------- | ------------------------------------- |
| 引出线方向   | 竖向（轴向） → 大概率不是 Φ                      |
| 引出线方向   | 横向（径向） → 大概率是 Φ                       |
| 视图类型    | 圆视图引出 → Φ 概率高                         |
| 视图类型    | 侧视图轴向 → Φ 概率低                         |
| 与技术要求交叉 | 弹簧"自由高度=45mm" → 侧视图标的 45 必为高度（即使看似 Φ） |


**任一信号触发** → 单独裁剪 200×200 px 局部放大复核。

## 常见误读案例（必看）

### 误读 1：① ↔ Φ 视觉混淆

```
现象：M01 ① 45.0±1.0 被读成 ① Φ45.0±1.0
真相：① 是编号圆圈，45.0 是自由高度（无 Φ）
诊断：标注在弹簧侧视图轴向 + 技术要求"自由高度=45mm"
修复：300 DPI + 视觉确认（Step 7）
```

### 误读 2：把几何角度当运动行程

```
现象：P07 ④ "60.00° 与护套旋转配合" 被理解为"旋转 60°"
真相：60° 是两特征之间的几何位置间距；"与护套旋转配合"是这些特征的功能注释
诊断：° 前没有"旋转/转动"等动词 = 位置角度
工程意义：360°/60°=6 → 提示有 6 个均布特征
修复：应用 Step 6.2 + 区分位置角度 vs 行程角度
```

### 误读 3：编号位置错位 / 串号 / 缺号

```
现象：P01 从 ④ 开始所有编号错位 1-2 个；⑬ Φ38 是从 P02 串过来的；⑧⑨⑪ 直接缺
诊断：没做编号连续性检查；没逐区域定位每个编号
修复：Step 6.1 强制运行；缺号必须回去重读对应区域
```

### 误读 4：n 类型字母前缀漏掉

```
现象：⑥ 2e-27.5 被简化成 ⑥ 27.5
真相：丢失"2 个 e 类型特征"信息，影响理解周向分布
修复：Step 6.3 正则强制捕获前缀
```

### 误读 5：括号注解读漏 / 改字

```
现象：P02 ⑲ "(P07连接筋位)" 被读成 "(P07连接部位)"
真相：括号内是关键配合注释，"筋位"特指有筋条结构的配合区，与"部位"不同
修复：Step 5 中"括号注释逐字保留，不能复述"
```

### 误读 6：公差形式简化

```
现象：⁺⁰·¹⁻⁰ 被简化为 ±0.1
真相：⁺⁰·¹⁻⁰ 只能向正，± 允许向负，工程含义完全不同
修复：Step 6.4 公差形式禁止简化
```

### 误读 7：忽略"符合 3D 图纸"标注

```
现象：对 P05 "凸点 1 结构符合 3D 图纸" 直接写完整描述
真相：标注明确说 2D 图不全
修复：自动识别此类注释，加入 C 级清单
```

### 误读 8：把"从圆心发出的细实线"当作半径引出线

```
现象：P03 ④ 24° 的上方那条细实线,连续四版都被解读为"从圆心出发的
      半径",试图把它对应到圆周某个齿或卡扣:
        V1 = 解锁旋转角
        V2 = 15 齿均布的齿间距
        V3 = 15 对齿的对中心距
        V4 = 中心扭转卡扣某"受力直边"的延伸线 (依然错!)
      每一版都用"3D 投影里找直线边"来验证,但方位没校准,找不到。

真相(V5,已用代码证实):24° 是 P03 中心扭转卡扣 "C 形叶片" 外缘**弧段**
      的两个端点连线与水平 B-B 的夹角。4 个叶片呈 90° 对称,每个叶片外缘
      弧段端点连线方向 ±24°/±156°,对应 6 条端点方向:
        (+2.05,+0.97) → (+2.94,+1.36)  = +24.0°
        (-2.05,-0.97) → (-2.94,-1.36)  = -156.0°
        (+2.31,+2.23) → (+0.50,+3.17)  = +152.5°
        ...等6条
      每条红边长度 ≈ 0.97 mm,从 R≈2.25 延伸到 R≈3.25。
      这些是**弧段的端点连线**,不是"直线边",所以纯"直线方向统计"会漏。

诊断信号(任一出现就该停下做 3D 投影对照):
  - 圆视图中心区域线条异常密集,难以区分
  - 角度尺寸的"靠圆心端"落在一组复杂线条之中而非单独端点
  - 360°/θ 整除后,想象出来的"均布特征数"在圆周上数不出来
  - 强行用"一对齿"、"成对分组"等非标准概念解释齿数差异

修复:
  1. 先按 Step 6.2-bis 做**方位校准**(这一步最致命,下面"误读10"详述)
  2. 方位对齐后,遍历投影所有边(含**曲线**,用端点连线方向),统计方向分布
  3. 不只统计直线边,**还要把弧段的端点连线**、**相邻折线的整体方向**一并纳入
  4. 若 θ° 方向一条也没有,则 θ° 不是"某条边与基准的夹角",必须把含义标为"工程师确认"
  5. 补做中心特写(R<10)截图,重点看圆心附近是否有复杂实体结构
  6. 禁止用"可能是一对""可能分组"这种模糊假设继续往下推理
```

### 误读 10：HLR 投影没做方位校准,整图旋转 90° 而不自知

```
现象：P03 ④ 24° 连续四版解错的最底层原因不是"看错线",而是
      **HLR 投影画面整体和 2D 图相差 90°**,所有角度都读错 90°。
      表面上梯形齿"大致对得上"(因为它们 4 次对称,旋转 90° 也能叠),
      非对称的模穴号 Y 字母才是唯一能暴露方位错位的基准。

具体错法：
  错误: gp_Ax2(origin, (0,1,0), (0,0,1))
        画面 x 方向 = Vx = (0,0,1) → 3D +Z
        画面 y 方向 = N × Vx = (0,1,0) × (0,0,1) = (1,0,0) → 3D +X
        结果:3D +X(Y字母)出现在画面 y 轴方向=12 点,而 2D 图里在 3 点
            3D +Z(梯形齿)出现在画面 x 轴方向=3/9 点,而 2D 图里在 12/6 点
        整张图旋转了 90°。

  正确: gp_Ax2(origin, (0,-1,0), (1,0,0))
        画面 x = Vx = (1,0,0) → 3D +X  → Y 字母在 3 点 ✓
        画面 y = (0,-1,0) × (1,0,0) = (0,0,1) → 3D +Z  → 梯形齿在 12/6 点 ✓

根本原因:cadquery/OCP 的 gp_Ax2(P, N, Vx) 里,**画面 y 方向由 N 和 Vx
       共同决定(叉积),不是 Vx 自己**。仅靠"改 view_dir = ±Y"不足以
       覆盖所有方位可能,必须同时枚举 Vx。

诊断信号:
  - 角度尺寸的"靠圆心端"落在一处复杂区域,读不出对应边
  - 方向分布统计找不到 θ° 方向的任何直/曲线
  - 3D 投影大致"能看"但字母 / 非对称标记位置不对

修复(强制):
  1. 先用代码扫出 2D 图中 2 个以上非对称基准的 3D 真实坐标(模穴号字母
     位置 / 非对称凸台 / 编号圆圈位置)
  2. 在 2D 图上读出这些基准的方位角(相对水平 B-B 或 A-A)
  3. 枚举 8 种 gp_Ax2 组合(2 个 view × 4 个 Vx),选让所有基准都对齐的
     那一组(差值 ≤ 5°)
  4. 校准合格后再进入"6.2-ter 引出线追踪 + 投影交叉验证"
  5. 方位错的投影,下面所有分析必须推翻重做,不能局部修正
```

### 误读 9：把"中间环带倾斜凹槽"当作径向小齿

```
现象：P03 圆视图中间环带上看到一排"短矩形"特征,被反复描述为
      "内圈密集小齿,均布 15 个,齿间距 24°"。

真相：这些短矩形是"倾斜凹槽"在投影平面的长边——凹槽方向约 60°/120°
      (非径向),且呈分组非均布分布。HLR 投影里光这一类方向就有 32
      条直线边,远多于"径向"方向的边。

诊断:在 3D HLR 投影中统计直线边方向分布,若最主导方向是 60°/120°
      这种"斜向",就要怀疑所见"小齿"是斜向凹槽而非径向齿。

修复:写周向特征前,先完成方向分布统计;"均布齿"是强假设,必须用
      投影数齿+角度对应双重证据。
```
