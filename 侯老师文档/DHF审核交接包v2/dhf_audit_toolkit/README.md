# DHF 审核工具包（给同事复用）

> 目标：让任何同事在**自己的电脑**上，能审自己产品线的 DHF/DMR（全部或一部分）。
> 分两层能力——**机械层（纯脚本，秒出）** + **语义层（Claude Code，懂判断）**。

---

## 能力分两层

| 层 | 工具 | 需要什么 | 能查 | 跑多久 |
|---|---|---|---|---|
| **机械层** | `check_residue.py`（本目录）| 装个 Python 3，无需AI | 模板残留、异类型号、占位符未改 | 几秒 |
| **语义层** | Claude Code + `skill/` 各阶段check skill | Claude Code | 槽位法、下游≥上游、角色串联、法规判断 | 几分钟/段 |

机械层先跑（清掉最低级、最高频的残留/占位符），语义层再上（做真正的内容审核）。

---

## 第一步：把 DHF 转成 Markdown（两层都需要）

AI 和脚本都读不了原始 .doc/.xls。先用转换工具把你的 DHF 文件夹转成 Markdown + 页面PNG（用现有的 conversion-toolkit-skill）。
- `.doc/.xls` → `.md`（正文）
- 同时保留 `sheet_pages_png/`（勾选框、图必须看图）

转完得到一个 `XXXX_MD/` 文件夹。

---

## 第二步：机械层——跑残留扫描（秒出，照命令敲）

```bash
# 进到工具包目录
cd dhf_audit_toolkit

# 跑你的产品（把路径和型号换成你自己的）
python check_residue.py  "你的MD文件夹路径"  --product 你的型号  --out 报告.csv

# 例：冲牙器，额外把"体温计/雾化器"当异类词，补自己的旧型号
python check_residue.py  "D:/.../CYQ_MD"  --product CYQ  --foreign 体温计,雾化器,血压计  --models 旧型号A,旧型号B  --out 冲牙器机械校验.csv
```

**看报告（Excel打开 报告.csv）：**
- `异类品类残留`（血压计/袖带/耳机…）→ **基本都是错**，模板没改干净，优先清
- `异类型号残留` → 区分：**复用件**（如沿用某成熟机型，合法，标"待确认"）vs **残留**（不该出现的旧型号，要清）
- `占位符未替换`（XXXX/待填/＿＿）→ 模板没填，要补

> 本案 PT9L 实测：一次扫出血压计/袖带20条、FDIR/PT9C真残留、占位符65条。

---

## 第三步：语义层——Claude Code 做内容审核

在 Claude Code 里打开你的 DHF 目录，让它按方法论审。三种粒度，挑一个：

**A. 审一个阶段**（最快）
> "用槽位法审 04设计输入：把每个参数抽成槽位，和上游(01客户需求)+下游(08验证)逐一比对，按 下游≥上游 标不一致。"

**B. 审一个工程师的责任范围**（可问责）
> "把硬件工程师签字的所有文件拉到一起，核电流/MCU/电池/传感器参数是否自相矛盾。"

**C. 审整链**（最全，参照 PT9L 的三段式）
> 参照 `PT9L_CHECK/PT9L-DHF审核方法论-汇报版.md` 的 4 轴，分阶段跑。

**给 Claude 的基线**（让它别跑偏）：
- 把你产品的法规基线、检查项放在 `XX_CHECK/` 下（参照 PT9L_CHECK 的 stage_XX_check_items.md / us法规基线 结构）
- 告诉它已拍板的事实（市场、注册路径、签名日期是否查等）

---

## 四条铁律（同事审核时必须守）

1. **下游≥上游**：下游只能覆盖/扩大，不能收窄
2. **正文封闭**：结论要正文逐字证据，标题/文件名/勾选行不算
3. **仅美国时**：欧盟/中国标准非强制（裁剪要写N/A理由；反向引用作美国判定=真错误）
4. **一致性≠正确性**：脚本和AI能查"对不对得上"，**"值本身对不对"必须工程师拍**（如传感器几根线、静音是按钮还是开关）

## 机械层脚本（已实现，纯Python无需AI）
- `check_residue.py`：模板残留/异类型号/占位符扫描
- `check_params_numeric.py`：**Tier1 数值一致性**——读参数明细长表，单位归一(℃/℉、A/mA/µA、mm、s)+区间/容差/边界解析+点落区间内判一致，剔写法误报，只报归一后仍冲突的（近零误报）。`python check_params_numeric.py 参数明细.csv --product XX --out 冲突.csv`。注:精度/分辨率(带温度段+重复性歧义)不做确定性比对,交LLM语义层。
- `check_table_diff.py`：**Tier1 行级 key-join 精确 diff**——比两份同构表(BOM/组件清单/版本前后)，按主键(物料编码/图号)对齐，出 仅A/仅B/值不同。适合"同一BOM在两阶段/两版本是否漂移"。`python check_table_diff.py A.xls B.xls --labelA T1 --labelB 设计输出 --out diff.csv`。**边界**:仅适用同构表;跨异构表(BOM↔清单↔WI)对账需Tier2列级schema匹配。

## Tier2 跨异构表对账（混合：LLM抽取 + 确定性核对）
- `check_bom_crosswalk.py`：**BOM↔清单↔WI 跨表对账**。输入统一记录表(来源,品名,用量,规格,图号,物料编码)——标准表(BOM/清单)确定性抽(列同义词映射,**无需嵌入模型**)，WI散文用 LLM 抽成记录；工具按品名规范化(同义词+模糊)聚合每源用量/规格/图号，核对：用量冲突/规格冲突/图号冲突(真冲突) + 范围差异(信息项,人工看)。`python check_bom_crosswalk.py 记录表.csv --out 对账.csv`
  - 实证(PT9S 总装ABOM↔装配WI)：抓到 **螺钉 ABOM=10 vs WI=9** 真冲突(确定性复现了原只LLM发现的)。
  - **边界(诚实)**：跨异构表对账非近零误报——范围差异(已降级信息项)、LLM抽取瑕疵(如把"3颗螺钉"误挂后壳)难免，属"低置信进人审"的候选生成器,非自动放行。
  - 列对齐：这些标准化DHF表用列同义词映射即可，**不需要 bge-m3 嵌入**；真要对任意陌生表头再上嵌入召回。
