## 0. 一句话

把"一堆 DHF/DMR 文档互相对不对得上"拆成**可判定的子问题**，**沿两条正交轴各扫一遍**——
**阶段轴**（按文件夹 01→DMR，查每阶段内"活干完没"=完备性）+ **维度轴**（按检查类型横扫全库，查"大家的活对不对得上"=一致性）——
每条结论必须**回正文拿到逐字证据**（拿不到判 NEI，不许判通过），并**逐条对抗证伪**才算数。

## 1. 核心升级：双轴审核（V2 的关键）

V1 的中心洞察、也是 V2 实证的事：**只按阶段/工种扇出，会对"接口"失明**——错误最爱藏在工种与工种、阶段与阶段的接缝里，而按阶段切正好把接缝劈成两半，谁都不看。

| 轴 | 怎么扫 | 抓什么 | 我们怎么验证的 |
|---|---|---|---|
| **阶段轴**（原有） | 按文件夹 01 立项→…→DMR，每阶段一个 agent，查阶段内完备性 + 4 子轴（纵向下游≥上游/横向参数槽位/角色串联/反向完备性） | 漏项、收窄、单阶段内矛盾 | PT9L 73 条 / PT9S 146 条 |
| **维度轴**（V2 新增·正交） | 按 7 种检查类型，每类一个 agent 横扫全库 | **跨文档/跨工种接口处的**数值对不齐、断链、收窄、矛盾、BOM不配平、版本混用 | **再挖 +54 条**（去重+证伪后） |

**结论：两轴正交，缺一漏一半。** 阶段轴管"每个人活干完没"，维度轴管"大家的活对不对得上"。先跑阶段轴，再跑维度轴横切。

## 2. 七个检查维度（维度轴的内容 + 实证战果）

每个维度 = 一类可判定的子问题 + 算法思路（融自 V1 §4）+ 本次实证抓到的真例子。

| 维度 | 查什么 | 算法思路（融自 V1） | 实证净新增(PT9S/PT9L) | 抓到的真例 |
|---|---|---|---|---|
| **可追溯断链** | 需求→输入→输出→验证→确认 逐参数查断链；每个风险控制有无验证；DHF清单每项是否落地 | 属性图多跳；闭世界完备性约束 | 6 / 7 = **13** | PT9L：电流参数下游有验证、上游设计输入**整条没有**(反向断链)；唯一追溯件只覆盖软件、不含器械级。PT9S：4份型式试验/EMC报告**占位"报告编码"无实体却判合格** |
| **BOM对账** | EBOM/ABOM/包装BOM/组件清单/WI物料/工序大纲/PFMEA 跨表配平 | 列级schema匹配+单元格key-join diff+公差 | 3 / 6 = **9** | PT9L：螺钉WI用9颗 vs BOM 10颗；缓冲垫/快速指南**在BOM里缺录**；装箱数三方不闭环。PT9S：EEPROM型号三处不一致 |
| **角色串联** | 同一工程师名下文件参数自洽；评审独立性(一人多职) | — | 4 / 5 = **9** | PT9L：侯广伟一人占技术负责人+软/硬/结构四主管，T1评审一人四席，审核=批准塌缩。PT9S：同一"品质工程师"署两个人 |
| **矛盾措辞** | 对立陈述：需临床vs免临床/版本日期打架/同参数互斥值/单文件内部判据矛盾 | 对立子断言对撞+簇级长上下文整读 | 3 / 5 = **8** | PT9L：说明书清洁等待"15分钟"vs"5分钟"；灭菌判据自相矛盾。PT9S：两版IFU并存、旧版残留vibration(额温计没有) |
| **版本漂移** | 同号多版本/整树副本/多版并存未作废/版本方向倒置 | MinHash+containment归族定方向 | 4 / 3 = **7** | PT9L：上下盖图纸两版日期方向倒置；彩包装DHF清单V1.0 vs实际V2.0。PT9S：标签审核表4个标签编号全树孤号 |
| **不收窄** | 下游区间⊆上游(量程/人群/环境/精度) | 区间包含判定(containment双向算) | 3 / 2 = **5** | PT9S：标签审核表把工作温度下限/±0.2℃精度带/适用人群都收窄了 |
| **数值一致** | 同一参数多处取值，区间+单位归一比对 | 区间算术+pint单位归一+Decimal精确判定(剔写法误报) | 0 / 3 = **3** | PT9L：常温标定23±2℃ vs 25±1℃(且单文件内自相矛盾)；精度测试点数3 vs 4 |

> 观察：**越成熟的 DHF，数值/BOM/版本类跨文档冲突越多**（PT9L 有完整 DMR/工序，挖到数值3+BOM6；PT9S DMR 还没产出，这两类自然少）。

## 3. 五层地基（决定"能不能审"，V1/V2 一致）

1. **工具层**：.doc/.xls/.pdf → Markdown + 截图（AI/脚本读不了原始件；勾选框/图配 PNG）。已脚本化：`convert_*.py`（Word COM + xlrd + openpyxl + fitz）。
2. **提取层（地基中的地基）**：抽**参数实例长表**（行=参数实例，列=参数名/值/单位/上下限/出处文件/版本/阶段）。**维度轴的数值/不收窄/BOM 全站在这张表上**。抽错=满盘错。
3. **检查层**：阶段轴 4 子轴 + 维度轴 7 维度。
4. **输出层**：错误总表（严重度/证据/建议/责任人）+ 检测报告(HTML)。
5. **封闭层**：结论必须正文逐字证据支撑。

## 4. 四条铁律 + 三条新信条（违反任一出假结论）

**铁律**：
1. **下游≥上游**：只能覆盖/扩大，不能收窄。
2. **正文封闭**：结论要正文逐字证据，标题/文件名/清单一行/空勾选都不算。
3. **看清市场**（本案仅美国）：欧盟EN/中国GB 非强制；裁剪写 N/A 理由；**反向引用 EN/GB 作美国判定 = 真错**。
4. **一致性≠正确性**：值本身对不对必须工程师拍；审核只判一致性+完备性，但要把可疑值标出来。

**V2 新增三信条**（从 V1 融入、本次实证有效）：
5. **NEI 纪律**：找不到正文证据 → 判"证据不足(NEI)"，**绝不默认通过、绝不编**。
6. **相似≠一致 / 双向原文引用**：判定必须给**具体冲突值 + A文件值 vs B文件值**两侧原文，不能只说"对不上"。
7. **逐条对抗证伪**：每条发现派一个"挑刺"agent 回正文试图反驳，证据不实/其实一致/写法误报就毙掉。**本次 PT9S 33→23、PT9L 37→31，证伪毙掉了约 1/4 的候选**——这步是防"自信地错"的关键。

## 8. 边界（别越界）

- **一致性≠正确性**：审核抓"对不对得上、全不全"，**值本身对不对要工程师拍**（传感器几根线、静音是按钮还是开关，都是 PM 纠的）。
- **NEI 不是失败**：抽不到证据如实标 NEI，比假装通过有价值。
- **缺口也是发现**：如 PT9S DMR 文件夹空 = 设计转换未完成，本身是 critical，不是"没查到"。
- **对抗证伪会毙掉约 1/4 候选**：这是诚实，不是损失——留下的每条都回正文核过。
